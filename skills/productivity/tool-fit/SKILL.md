# Tool Fit

Choose tools by the task's evidence and the user's next decision, not by a product name. Before a
tool-sensitive step, inspect the relevant capabilities available in this host. Use only the ones
that improve the result; do not turn the capability list into a checklist.

- For workspace facts, inspect the actual files, state, and receipts. For a user-supplied or linked
  connected source, use an available authorized connector to inspect the original. Search an
  available connected source when relevant project evidence may live there. For current external
  facts, use available search or browsing and open the source itself. Cite sources actually
  inspected and distinguish them from inference.
- For an explanation or review, respond in chat so the useful result is visible there. Use an
  available in-chat diagram, chart, generated or edited image, canvas, or interactive view when
  it clarifies relationships, comparisons, or a decision. Keep simple facts and updates as text.
  Match the visual to evidence and inspect its rendering when the host permits.
- Create a file when the user requests one, a skill's durable output requires it, or the work
  needs a reusable artifact. If the host can preview that artifact, show the preview with a short
  summary and a link to the source. Use a webpage or hosted view when interaction or substantial
  user-facing material justifies it.

Follow the host's tool instructions and the active task's access and action boundaries. Existing
authorized read-only connections can supply evidence. New account connections, paid services,
external writes, and publication need their own authority; a useful feature does not supply it.
When a fitting capability is unavailable, use the best available source or format and state any
material verification or display limit.
